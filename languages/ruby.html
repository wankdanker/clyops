Ruby

Requires Ruby 3.1+. Complete API reference · Shared behavior

Install and run

gem install clyops

Save the following as quickstart.rb:

require "clyops"

cli = Clyops::Cli.new(name: "docs-demo")
cli.opt "NAME", "name", "n", "World", "Who to greet"
cli.opt "COUNT", "count", "c", "1", "Repeat count", "Options", "int:1-3"
cli.opt "VERBOSE", "verbose", "v", "flag", "Verbose output"
args = cli.run
puts "#{args.NAME} #{args.COUNT} #{args.VERBOSE}"

ruby quickstart.rb --name Ada --count 2 --verbose
# Ada 2 true
ruby quickstart.rb --help
ruby quickstart.rb --help-json-schema
ruby quickstart.rb --count invalid
# Validation error; exit status 1

Editor support and resolved values

YARD comments describe public methods and parameter/result types. The gem includes sig/clyops.rbs for tools that consume RBS. Editor support differs by language server; dynamic args.NAME access cannot imply a specific registered field type.

Commands, relationships, secrets, effects and I/O

Add these registrations before calling run. A CLI level has either subcommands or positional arguments.

db = cli.command("db", "Database tasks")                # a command: mytool db ...
migrate = db.command("migrate", "Apply migrations")     # mytool db migrate
migrate.opt "TO", "to", "", "optional", "Target version", "Options", "int"
migrate.set_effects("destructive")                      # read-only, idempotent, destructive, network
cli.opt "TOKEN", "token", "t", "", "API token", "Auth", "secret"  # masked in help and values_json
cli.exclusive("json", "quiet")                          # also requires(a, b...) and one_of(a, b...)
cli.set_stdin("Audio to transcribe", "audio/wav")       # and set_stdout(description, content_type)
cli.role("progress", "out", "Progress", "application/x-ndjson")  # then cli.emit("progress", { pct: 50 })
args = cli.run                                          # args.command == ["db", "migrate"]

cli.command_path is the selected command words. Commands share the program's options (accepted before or after the command words) and config file; each has its own help (mytool db migrate --help), schema and completion. See the spec sections 1.3 to 1.7.

Completion values from your program

complete(name) { |request| ... } (or complete(name, callable)) lists the values of an option or argument that only the program can find, such as the instances registered in a directory. They are offered when the user presses Tab, and to tooling that asks with --complete-values (the HTTP API, MCP server and web runner):

cli.opt "INSTANCE", "instance", "i", "", "Instance to target"
cli.complete("instance") { Dir.glob("/var/lib/myapp/instances/*.json").map { |f| File.basename(f, ".json") } }

The block gets a Clyops::CompleteRequest: words (the words typed after the command words, for completers that depend on another option), prefix, limit (0 means no limit) and offset. By default it may return every value and the library keeps the ones starting with prefix and pages them. With paged: true it applies prefix, offset and limit itself, which suits a database:

require "sqlite3"
cli.complete("host", paged: true) do |request|
  SQLite3::Database.new("app.db").execute(
    "SELECT DISTINCT name FROM hosts WHERE name LIKE ? ORDER BY name LIMIT ? OFFSET ?",
    ["#{request.prefix}%", request.limit.zero? ? -1 : request.limit, request.offset]
  ).map(&:first)
end

The block runs only for --bash-completion and --complete-values, so keep it quick. Raising keeps the rule's shell completion. prog --complete-values host al 10 0 prints {"values":[...],"more":false}; in code, cli.complete_values("host", "al", 10, 0) returns a Clyops::ValuesPage (values, more). It doesn't validate: check the value after run if only listed values are allowed. See the spec sections 9.2 and 9.3.

Parsing and errors

Use run for a standalone program: it displays help/schema/completion and exits for those requests, or exits with status 1 on invalid input. Use the non-exiting parse variant in libraries and tests; check its outcome before reading resolved values. Registration errors (duplicate names, unknown rules, or commands mixed with positionals) are programming errors, distinct from invalid user input. See the native reference for the language's result and error types.
